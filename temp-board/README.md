- `boards-api.php?action=posts&board=...&page=...&q=...` GET 조회 추가. 독립 관리자 세션 검사 유지. 서버에서 등록된 게시판인지 확인한 뒤 설정의 write_prefix를 사용.
- 검색과 페이지 조회는 준비된 SQL로 처리. 게시판 ID/페이지/검색어 형식 검증, 검색어의 LIKE 와일드카드 문자 처리. 댓글은 목록 개수에서 제외하고 답글은 포함. 공지 우선 후 그누보드 기본 글/답글 순서로 정렬.
- 게시글은 페이지당 20개, 숫자는 최대 5개와 첫/이전/다음/마지막 이동. 검색 시 첫 페이지, 존재하지 않는 높은 페이지는 마지막 페이지로 보정.
- `posts-query.php`는 인증된 API 내부 포함만 허용. 목록 SELECT와 COUNT만 수행. 본문·이메일·IP·전화번호·첨부파일은 조회하지 않으며 조회 수도 증가시키지 않음.
- 원본 보기는 새 창의 그누보드 게시글로 이동. 이 링크에서는 그누보드의 정상 권한·조회 수 처리 적용. 현재 독립 대시보드 로그인은 그누보드 로그인으로 전환하지 않으므로 비밀글 원본 확인은 별도 권한 필요.
- 검색 중 이전 응답 취소/무시, 메뉴 이탈 시 요청 취소, 20초 시간 제한 및 오류 후 재시도. 페이지 요청 중 기존 행 높이를 유지하여 스크롤이 갑자기 위로 올라가는 현상을 줄임.
- 게시판/게시글 JS 주소에 파일 수정 시간을 붙여 업로드 후 이전 스크립트 캐시 적용 방지.
- Edge 1440/375px 및 실제 HTTP 검사 40건 통과: 미로그인/직접 포함 파일 차단/잘못된 입력/POST 차단, 20개 목록/페이지/검색/마지막 페이지/0개/실패/연속 검색/다른 메뉴 이동/텍스트 이스케이프/가로 넘침/JS 오류. 성공 목록은 브라우저 응답 fixture 검증이며 실제 DB 게시글 SELECT 성공은 운영 확인 대기.
- 생성: `temp-board/posts.js`, `temp-board/posts-query.php`.
- 수정: `temp-board/boards-api.php`, `temp-board/boards.js`, `temp-board/index.php`, 이 문서, `RESPONSIVE_PROGRESS.md`. CSS/이미지/운영 DB 변경 없음.

### 이번에 서버에서 확인할 것

현재 temp-board 폴더를 운영 서버에 갱신 후 새로고침 → 게시판 관리 → 각 게시판의 '게시글 목록'. news/notice의 실제 제목이 표시되는지, review/qa의 빈 목록과 제목 검색이 정상인지 확인. 실패하면 확인 코드만 전달. DB 설정 파일은 변경하지 않음. 이번 구현도 쓰기·수정·삭제·업로드와 관리자 권한 연동은 포함하지 않음.

## 3단계: 게시글 작성·수정·삭제·첨부 업로드 (2026-10-14)

- 게시글 목록의 운영 연결은 사용자가 정상 동작 확인. 이번 추가 작성/수정/삭제/업로드는 로컬 구현·격리 테스트 완료이며 운영 적용 확인은 대기.
- `post-action.php`: 독립 관리자 세션을 먼저 검사. 변경은 POST + 관리자 CSRF + 게시판/게시글/작업에 묶인 일회용 요청 토큰 검증. GET은 편집 정보 조회만 허용.
- 기존 그누보드의 `/board/common.php`와 `bbs/write_update.php`, `bbs/delete.php`를 그대로 호출. 원본 DB 저장 SQL/첨부 이동/댓글·포인트·최근글·공지·글 수/썸네일·캐시 정리/확장 훅을 새로 복제하지 않음. 기존 board 파일과 DB 설정은 수정하지 않음.
- 현재 고정 관리자 계정의 작업 권한은 서버 config의 cf_admin을 통해 기존 최고관리자 계정으로 매핑. 해당 회원 존재/레벨 10/탈퇴·차단 상태 확인. 요청값으로 회원이나 권한을 지정할 수 없음.
- 대시보드 세션을 활성 상태로 유지하며 G5_SESSION_NAME도 해당 이름으로 지정. 일반 사이트 회원·자동 로그인 쿠키를 가져오거나 별도의 공개 그누보드 로그인 쿠키를 만들지 않음. 응답은 관리자 경로의 HttpOnly/SameSite=Lax 쿠키를 유지.
- 공통 실행은 익명 컨텍스트에서 시작해 관리자 전용 자동 DB 정리가 실행되지 않도록 하고, G5_IS_CLI로 방문 기록 제외. 공통 초기화 후에 해당 요청의 관리 권한을 매핑. 사이트별 extend/skin 코드는 설치본의 원래 동작을 따름.
- 그누보드 작성/수정/삭제 요청 토큰 및 수정 게시판·글 세션을 위임 직전에 설정. 성공 훅과 alert/goto_url 훅을 받아 JSON 응답. 저장 후 원글 존재/삭제 후 부재 확인. 경고 메시지가 있는 성공은 경고도 표시.
- 중복 요청은 저장된 완료 응답을 반환하며 처리 중/결과 불명 요청은 자동 재실행하지 않음. 요청 토큰은 20분 유효, 세션에 최근 약 40개 편집 정보 유지. 다른 화면에서 본문·옵션·공지 상태·첨부가 바뀌면 다시 열도록 안내.
- 오류 출력/리다이렉트/설치 화면은 JSON에 그대로 섞지 않음. 접속 비밀번호·SQL·서버 경로를 응답에 내보내지 않으며 서버 로그에는 오류 종류와 코드/파일명/줄만 기록.

### 편집 화면과 업로드 범위

- 기존 관리자 dialog/모바일 바텀시트 디자인 사용. 제목/본문/분류/일반 텍스트·HTML·HTML 자동 줄바꿈/공지·비밀글/관련 링크 2개 편집.
- 본문은 텍스트·HTML 원문 편집 방식이며 새 WYSIWYG 라이브러리는 설치하지 않음. 기존 영상 iframe/HTML 원문을 유지. 본문 미수정 상태의 multipart 줄바꿈 변화는 기존 저장 원문으로 보정.
- 원 작성자·기존 메일 옵션·wr_1~wr_10 등의 확장 필드는 보존. 첨부 설명은 native writer가 직접 SQL escape하므로 중복 escape하지 않음.
- 이미지/파일은 저장 버튼을 누를 때 그누보드의 `data/file/{게시판}/`에 저장. 저장 전에는 브라우저 미리보기만 사용. 기존 파일 유지/교체/설명 수정/삭제 선택 가능. 빈 슬롯과 기존 파일 번호 보존.
- 허용 형식: JPG/JPEG/PNG/GIF/WEBP, PDF/TXT/ZIP/DOCX/XLSX/PPTX, MP4/WEBM. 실제 서버 MIME와 이미지 구조 검증, PHP/HTML/SVG/JS 등 실행 가능한 확장자와 위험한 이중 확장자 차단.
- 게시판 bo_upload_count/bo_upload_size와 PHP upload_max_filesize/post_max_size 제한 사용. 파일당 실제 크기/전체 용량 및 대상 폴더 쓰기 권한 검사 후 native writer 호출. mysqli 및 fileinfo PHP 확장 필요.
- 삭제 확인창은 운영 게시글·댓글·첨부의 삭제와 복구 불가를 명시. 저장 중 중복 제출/닫기 방지, 변경한 내용 닫기 확인, 결과 불명 시 목록 확인 안내.
- 교육·프로모션·임상·수료지점의 콘텐츠 저장/이미지 업로드는 여전히 임시 저장. 게시판 추가·삭제/설정 관리도 이번 범위 아님.
